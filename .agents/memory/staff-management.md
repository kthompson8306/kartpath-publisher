# Staff Management — Key Decisions & Gotchas

## `zod/v4` subpath cannot be resolved by esbuild
The API server uses esbuild to bundle. `import { z } from "zod/v4"` fails at build time because esbuild cannot resolve the subpath export. **Always import from `@workspace/api-zod`** for validated types in route files — never import zod directly in `artifacts/api-server/src/routes/`.

**Why:** `lib/db` runs under tsx which handles subpath exports; esbuild bundling does not.

**How to apply:** Any new route that needs schema validation should import from `@workspace/api-zod` (generated by orval). If a type isn't there yet, add it to the OpenAPI spec and run codegen.

## JSX conditional wrapping in large components
When wrapping a large JSX block in `{condition && (...)`, the closing `)}` must be placed INSIDE the containing fragment (`<>...</>`) boundary, not outside it. Babel's JSX parser gives a misleading "Adjacent JSX elements" error pointing at the `</>` closing tag, not the missing `)}`.

**Why:** TypeScript's `tsc --noEmit` catches this cleanly with `)' expected`. Always run tsc before HMR to catch JSX structure errors early.

## Staff routes authentication pattern
`requireAdminAccess()` in `routes/staff.ts` does a second DB lookup after `requireStaff` to confirm the caller holds `publication:write` for the *requested* publicationId. This is required because `requireStaff` only confirms the user has access to *some* publication — not necessarily the one in the request body/params.

**How to apply:** Any staff-management endpoint must call `requireAdminAccess(req, res, publicationId)` after `requireStaff`.

## /complete endpoint — two sequential fetch calls in tests
The `/complete` route now makes TWO fetch calls in sequence:
1. Sidecar → signed GET URL (`POST /sign-url` or similar)
2. HEAD against that signed URL → 200 (exists) or 4xx (missing)

In integration tests, stub them with two `mockResolvedValueOnce` calls in order. An already-ready asset returns immediately without any fetch calls (test for `mockFetch.not.toHaveBeenCalled()`).
